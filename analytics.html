Measuring what matters

A guide for a college web and marketing team: the few numbers that show whether the website is doing its job, how Campus Kit marks the buttons behind them, and how to count those clicks without following anyone around the web.

Three numbers worth watching

A college website has a few jobs that matter more than the rest: getting students to apply, getting them to campus, and helping them find a program. Count those three things well before you count anything else.

Application starts

How many people click "Start your application." This is the number Admission cares about most, and the one the website can most directly change.

Compare each month with the same month last year, not with last month. Applications follow the deadline calendar, so a jump in November and a drop in December is normal.

Visit sign-ups

How many people click through to book a tour or sign up for an open house. A visit often comes months before an application, so a drop here is an early warning.

Read it next to the events calendar. If sign-ups fall in a month with no open house on the calendar, the fix is an event, not the website.

Program searches

What people type into the program search, and how many programs each search found. This is the one place visitors tell you, in their own words, what they're looking for.

A search that finds nothing is the most useful line in the report. It means you don't offer the program, or you call it something else. If people search for "pre-med" and the biology page says "pre-health track," add their words to the program's description so the search finds it.

Numbers to read with care

  • Page views on their own. A busy page can mean people can't find what they need and keep coming back to it.
  • Time on page. A long visit to the deadlines table might be confusion, not interest. A quick visit to a phone number is a success.
  • Bounce rate. Someone who reads the tuition figure and leaves got their answer.
  • Spikes after a news story. They're good for the newsroom but rarely move applications. Don't compare a month with a big story to one without.

Choosing a privacy-friendly tool

You don't need to know who a visitor is to count what they clicked. Many of the people using a college website are high school students, so collect as little as you can. A smaller tool also loads faster: every script added to a page counts against the performance budget.

Look for a tool that:

  • counts visits without cookies or an ID that follows people from site to site
  • doesn't store names, email addresses or full IP addresses
  • doesn't sell or share your data or use it for advertising
  • lets you choose how long data is kept, and delete it
  • can count named events, like the buttons listed below
  • has a dashboard you can share with Admission without setting up an account for each person

Plausible, Fathom, Simple Analytics, Matomo and GoatCounter are examples to compare against this list. Some can run on the college's own server. Check each one yourself, ask your privacy or compliance office before adding any tool, and say what it collects in the site's privacy notice.

How buttons are marked

Every button or form worth counting has a data-track attribute that names the action. It doesn't change how the page looks or works. A small script, added once you've chosen a tool, reads the name and sends it.

<a class="button" href="#" data-track="apply-start">Start your application</a>

When one page has the same action twice, data-track-place says which one was used. The giving page has a "Give online" button at the top, shown on phones only, and another in the sidebar:

<a class="button" href="#" data-track="give-start" data-track-place="top">Give online</a>
<a class="button" href="#" data-track="give-start" data-track-place="sidebar">Give online</a>

Rules for names

  • Say what the visitor did, in lowercase words joined by hyphens: apply-start, not button-3 or blue-cta.
  • Same action, same name, on every page. The tool already records which page a click happened on, so don't put the page in the name.
  • Mark actions, not menus. A click on "Admission" in the menu is already counted as a view of the admission page.
  • Never mark a field where people type a name or contact details. The staff directory search is left unmarked on purpose: what people type there is someone's name.
  • Add every new name to the table below. The automated check stops the site from publishing if a page uses a name that isn't in the table, or the table lists one no page uses.

Connecting a tool

This is a job for the web team, and it takes about an hour once a tool has been approved.

  1. Add the tool's script to the <head> of every page, following its instructions.
  2. Add the code below to the end of assets/js/main.js, and replace the line inside sendEvent with your tool's own call for a named event. Every tool listed above has one.
  3. Click each button in the table above and check that the event appears in the tool's live view.
  4. Update the privacy notice to say what is counted.
// Counts the buttons and forms marked with data-track.
// Not included in Campus Kit: add it only once a tool is approved.
function sendEvent(name, details) {
  // Replace this line with your tool's call for a named event
  console.log("Would send", name, details);
}

// Buttons and links
document.addEventListener("click", (event) => {
  const target = event.target.closest("a[data-track], button[data-track]");
  if (!target) return;
  sendEvent(target.dataset.track, { place: target.dataset.trackPlace });
});

// Search boxes that open the program finder (home page, page not found)
document.addEventListener("submit", (event) => {
  const form = event.target.closest("form[data-track]");
  if (!form) return;
  const words = String(new FormData(form).get("q") || "").trim().slice(0, 60);
  sendEvent(form.dataset.track, { words });
});

// The program finder's own search, which filters as people type.
// "change" fires when they leave the box, so each search counts once.
document.addEventListener("change", (event) => {
  const form = event.target.closest("form[data-track][data-filter]");
  if (!form || event.target.name !== "q") return;
  const words = event.target.value.trim().slice(0, 60);
  if (!words) return;
  const list = document.getElementById(form.dataset.filter);
  const found = list.querySelectorAll(":scope > li:not([hidden])").length;
  sendEvent(form.dataset.track, { words, found });
});

The search words are cut to 60 characters, so a long paste can't carry much. A search from the home page counts once, where it was typed: when the program finder opens with those words already filled in, nothing is sent.

A monthly check-in

Set aside 20 minutes in the first week of each month. Most months you'll make one small change, and that's the point.

  1. Compare application starts and visit sign-ups with the same month last year.
  2. Read the 20 most common program searches, and every search that found nothing. Add missing words to program descriptions.
  3. See which pages people were on when they clicked "Start your application." Make sure the pages that send the most people have a clear link to apply.
  4. Send Admission three sentences: what went up, what went down, and the one change you're making this month.
