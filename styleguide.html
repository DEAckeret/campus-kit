Style guide

The building blocks of every Campus Kit page. Each example shows the HTML underneath it, so you can copy a component into a new page and it will look right.

Color

Colors are set once in assets/css/tokens.css. To rebrand the kit, change the values there and every page updates. Contrast ratios are measured against white.

  • Spruce--color-spruce#1f5c4a, 7.8:1. Links, buttons, header.
  • Violet--color-violet#4f43c2, 7.2:1. Focus rings and accents.
  • Gold--color-gold#e8b23a. Athletics and highlights. Never use for text on white.
  • Ink--color-ink#1b2430, 15.6:1. Body text.
  • Ink, muted--color-ink-muted#4a5564, 7.6:1. Captions and secondary text.
  • Sky--color-sky#dce8f2. Tags and soft fills.
  • Mist--color-mist#f2f4f7. Quiet section backgrounds.
  • Violet tint--color-violet-tint#ecebfa. Callout boxes.

Type

Headings use Literata, a book serif designed for long reading on screens. Body text uses Public Sans, a neutral sans-serif built for government and public-service sites. Sizes follow a 1.25 ratio.

Form and thank-you message

For short forms, like "Report a website problem." Fields stack one above the other. Every field has a visible label; say "(optional)" in the label rather than marking the required ones. Put a hint between the label and the field and link it with aria-describedby. A required field left empty gets a red border after the visitor tries to send the form, and the browser says what's missing.

The thank-you message stays hidden until the address ends in its id, so point the form's action at it and it works without JavaScript. With JavaScript, focus moves to it so screen readers read it first. In the demo the fields have no name, so nothing is sent; on a real site, add names and point action at your form service with method="post". Show the thank-you message.

For a process that has to happen in order, like applying or registering. It's a real numbered list, so screen readers announce how many steps there are. Keep it to five steps or fewer, and start each heading with a verb.

Table

For information people compare across rows, like courses or deadlines. Always give the table a <caption> and column headers. The <section class="table-wrap"> wrapper scrolls sideways when the table is wider than a phone screen. tabindex="0" lets keyboard users scroll it, and aria-labelledby pointing at the caption's id makes it a named region, so screen readers announce "Required core courses, region" instead of an unnamed group. Each caption needs its own id.

Program handout (print)

Every program page prints as a one-page handout for college fairs, on US letter or A4 paper. Add class="one-sheet" to the page's <body>: when printed, the type shrinks to fit, the menu and breadcrumbs drop out, and the sidebar becomes a row of contacts along the bottom. Add no-print to anything that only makes sense on screen, like the "On this page" links and buttons. A print-only block appears only on paper; use it for a short web address and the admission office's contact. Below, it's shown so you can see it. The "Print this page" offer appears only when JavaScript is running, since a button can't start printing without it. To see a handout, open the biology page and use your browser's Print preview. The automated checks fail if a program page needs a second sheet.

Demo contact links

The demo school is fictional, so its phone numbers and email addresses don't go anywhere. Give each one href="#" and data-demo-contact="phone" or "email". Clicking it opens a short note explaining what a real link would do. On a real college site, use tel: and mailto: links instead. Without JavaScript the link does nothing, and the number or address is still there to read. Long email addresses break onto a second line when space runs out, for example in a narrow column at 400% zoom, instead of making the page scroll sideways.

Counted buttons

Mark a button, link or search form that the web team wants to count with data-track and a name for the action. It changes nothing a visitor sees, and nothing is counted until the college connects an analytics tool. Use a name from the list of counted buttons, or add a new one there. When the same action appears twice on one page, add data-track-place to tell them apart.

Photos and images

Photos are often the first thing a visitor looks at and the heaviest thing on the page. Every photo needs three things: alt text that does the photo's job for people who can't see it, a file sized for the screen it's shown on, and a file small enough to load quickly on a phone.

Photo with caption

A photo in the text of a page, with a caption and credit. Save the photo at the widths in Sizes to save and list them all in the HTML. The browser downloads only the one it needs.

  • srcset lists the same photo at each width you saved, followed by its width in pixels (960w).
  • sizes tells the browser how wide the photo shows on the page: here, 44rem on wide screens and the full screen width on phones. The browser picks the smallest file that will look sharp, including on high-resolution screens.
  • <source type="image/webp"> offers the WebP files, which are smaller. Browsers that can't show WebP use the JPEG files in the <img>.
  • width and height are the size of the largest file. They let the browser save the space before the photo arrives, so the text doesn't jump. The photo still shrinks to fit the column.
  • loading="lazy" waits to download the photo until the visitor scrolls near it. Leave it off a photo at the top of the page, so that one appears as fast as possible.

This "photo" is a drawing made by scripts/sample-photo.mjs, because the college is fictional and has no photos. npm run check:images checks every page: each file in a srcset exists, is the width it claims and weighs under 250 KB, and every image has alt text, a width and a height.

Writing alt text

Screen readers read the alt text in place of the photo, and browsers show it when a photo doesn't load. Ask what the photo adds to the page, then write that.

  • It only sets a mood, and the text says everything: use empty alt text, alt="". Screen readers skip the photo. Never leave alt out, or some screen readers read the file name.
  • It shows something the text doesn't: describe that in one sentence, the way you would to someone on the phone.
  • It has words in it, like a poster or a sign: put the words in the alt text, or in the text beside it.
  • It's the only thing inside a link: say where the link goes, not what the photo looks like.
  • It's a chart: say what it shows in the alt text, and give the numbers in a table or the text, like the news story does.

Don't start with "Image of" or "Photo of"; screen readers already say it's an image. Say "drawing" or "painting" only when that matters. Keep it to a sentence or two, and put anything longer in the caption or the text. Describe people by what they're doing, and mention how someone looks only when it matters to the page. Name people only when the page is about them.

Sizes to save

A photo straight from a camera or phone is 4,000 to 6,000 pixels wide and several megabytes, which can take seconds to load on a phone. Save each photo at the widths below. The largest is twice as wide as the photo appears, so it stays sharp on high-resolution screens.

Save photos as JPEG at a quality of 70 to 80, and as WebP at 75 if your editing tool can. WebP is usually a third smaller: the drawing above is 85 KB as a JPEG and 53 KB as a WebP at 1440 pixels wide. Use PNG only for screenshots.

Heavy photos are the most common reason a page loads slowly. The performance report shows each page's speed score, and npm run check:images stops any photo file over 250 KB.

Before you upload a photo

  • Everyone who can be recognized in it has signed the college's photo release. Ask the marketing office if you're not sure.
  • It's cropped to the shape in the table, with nothing important right at the edge.
  • It's saved at each width in the table, and the largest file is under its target.
  • Location data is removed. Phones record where a photo was taken; most "Export" or "Save for web" options remove it.
  • The file name uses words, lowercase letters and hyphens, and ends with the width: biology-field-lab-960.jpg.
  • There's no text in the photo. Put words on the page instead, where everyone can read, search, zoom and translate them.
  • The alt text and caption are written.
