Site performance report

Every time the site changes, Lighthouse loads ten of its pages the way a phone on a slow connection would and scores them for speed, accessibility and search. If a page scores below its budget, the change isn't published. These are the scores for the version of the site you're looking at.

The budgets

A budget is the lowest score a page is allowed. Lighthouse scores each page from 0 to 100 in four areas.

What each score checks, and the lowest score allowed
ScoreWhat it checksBudget
PerformanceHow quickly the page shows its content and responds to taps.90 or higher
AccessibilityProblems a computer can find that block people who use screen readers, keyboards or zoom, such as missing labels or low contrast.100
SEOWhat search engines need to list the page well: a title, a description, links that say where they go, and permission to index the page.90 or higher
Best practicesSigns of a well-built page, such as no errors in the browser and images shown at the right shape.None, shown for reference

How the check works

  • The check runs in GitHub Actions on every change, using Lighthouse CI, Google's free tool for testing page quality.
  • Each page is loaded three times, because scores can move a few points from one run to the next. Each score is the middle of the three, and the speed figures come from the run with the middle performance score.
  • The pages are loaded from the test machine, not from the live site, so the scores measure the pages themselves rather than the web host. Fonts load from Google Fonts, as they do on the live site.
  • A perfect accessibility score doesn't mean a page is fully accessible. Automated tools find only some problems. Campus Kit also checks every page with axe and at 200% and 400% zoom, but testing with people who use assistive technology is still needed.
  • To change a budget, edit lighthouserc.json and the table above. The check stops if the two don't match.
